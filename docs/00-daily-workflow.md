# 日常制作与发布流程

本文是 `项目说明.md` 的执行版，供 AI 在新对话中核对步骤。用户不需要手动执行命令。

## 一、本地制作

1. 阅读根目录 `AGENTS.md`、`项目说明.md` 和目标测试的 `项目说明.md`。
2. 新测试先建立独立目录、`test.manifest.json` 和项目说明。
3. 在测试目录内完成题目、选项、算法、结果、页面和素材。
4. 接入共享兑换码授权，不复制后台或服务器。
5. 运行测试包校验、类型检查、平台构建和自动测试。
6. 启动本地服务，用浏览器检查电脑和手机尺寸。
7. 把本地地址交给用户体验，根据反馈继续修改。

本阶段不得推送 GitHub、构建生产镜像或修改 Sealos。

## 二、用户验收

只有下面这种明确表达才进入发布阶段：

> 本地验收通过，可以上传并正式开放。

如果用户仍在询问、比较或要求调整，继续留在本地阶段。

## 三、正式发布

1. 再跑一次完整自动检查。
2. 检查源代码和构建产物中没有密码、密钥、明文兑换码或本地数据库。
3. 备份生产数据库，并记录当前生产镜像摘要。
4. 形成一次说明清楚的 Git 提交并推送 GitHub。
5. 默认由 GitHub Actions 在 Linux 上构建 Docker 镜像并推送 GHCR。
6. 等镜像成功后更新 Sealos 镜像版本。
7. 检查 `/health/live`、`/health/ready`、后台登录和所有测试入口。
8. 记录镜像摘要、数据备份和验收结果。

## 四、失败处理

- 本地普通构建失败：修正后重新测试，不进入发布。
- 本机 Docker 不可用：按 `04-windows-docker-recovery.md` 识别已知故障；不让本机 Docker 长时间阻塞发布。
- GitHub 镜像构建失败：保留旧生产镜像，不更新 Sealos。
- Sealos 新镜像未就绪：保留日志并切回上一镜像；除非数据库迁移不兼容，否则不恢复数据库。
